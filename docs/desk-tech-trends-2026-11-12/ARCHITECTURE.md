# ARCHITECTURE: desk-tech-trends

> 결정 근거는 [PRD.md](PRD.md)의 「결정」 절. 현재 코드의 의존 방향(`scripts/` · `hooks/` · `page/` → `desk/`, 셋은 서로 import하지 않음)을 그대로 따른다. 회고 우편함(`desk/routine.py`)과 같은 모양으로 맞춘다.

## 구조

```
wiki ──쓴다──▶ trends_items (JSONL)          desk가 읽기만
                      │
page/server.py ── GET /trends ─▶ desk/trends.py ─▶ 오늘 3건 + 지난 미읽음 + 잔디 1년
                      ▲
                POST /trends/read ─ 잠금 · 재확인 ─▶ trends_reads (JSONL, desk가 덧붙임)
                POST /trends/mark ─ 잠금 · 재확인 ─▶ trends_marks (JSONL 이벤트, 마지막 줄이 이김)
```

## 결정

| 주제 | 결정 | 결정 주체 | 이유 |
|---|---|---|---|
| 모듈 | **새 `desk/trends.py`** (파싱 · 읽은 건수 집계 · 잔디 계산 · 읽음 덧붙이기). `desk/routine.py`와 합치지 않는다 | AI 가정, 반려 가능 | 회고와 동향은 줄 모양·규칙이 다르다. 파서·원자 쓰기 같은 공통부만 재사용한다(`routine`의 비공개 함수를 직접 import할지 `desk/atomic.py`로 옮길지는 구현 때 확인, 미확인) |
| 읽기 엔드포인트 | **`GET /trends`** — 오늘 동향 · 지난 날 미읽음 목록 · 잔디 1년치(날짜 → 건수 0~3)를 한 응답에 준다. 화면은 받은 대로 그린다. GET은 파일을 바꾸지 않는다 | AI 권장안 | ADR-009를 지킨다. 계산을 서버가 하면 화면과 서버의 숫자가 갈라지지 않는다(비명백 패턴 「서버 · 화면」 — 화면이 읽는 필드를 서버가 실제로 보내는지 브라우저에서 한 번 본다) |
| 쓰기 엔드포인트 | **`POST /trends/read`** — 글 id 하나를 받아 읽음 파일에 `{id, at}`를 덧붙인다. 토큰 헤더와 입력 검증은 `POST /pick`과 같다. **잠그고, 쓰기 직전에 읽음 파일을 다시 읽어** 이미 있으면 덧붙이지 않는다(멱등). 동향 파일에 없는 id는 거절한다 | AI 권장안 | 탭 둘이 같은 글을 거의 동시에 눌러도 줄이 하나다. 회고의 `/routine/answer`와 같은 규칙 |
| 북마크 | **`POST /trends/mark`**(이름은 구현 때 확정) — 글 id와 켬/끔을 받아 `trends_marks`에 `{id, on, at}`를 덧붙인다. 같은 모듈 `desk/trends.py`에 둔다. `GET /trends`는 글마다 북마크 여부와 북마크 목록을 준다. 읽음 상태와 독립이다 | AI 가정, 반려 가능(제품 결정은 Finn) | 읽음과 같은 잠금 · 재확인 · 검증을 재사용한다. 파일을 섞지 않아 잔디 집계가 북마크를 몰라도 된다 |
| 잔디 계산 | **글의 `date`로 묶어 그날 읽은 distinct id 수를 센 뒤 3으로 자른다.** 읽음 파일에서 같은 id가 여럿이어도 한 번. 동향 파일에 없는 id는 센 건수에서 뺀다. 날짜 기준은 서버의 `_today()` | PRD 결정(Finn) / 구현 방식은 AI | 지난 날 글을 오늘 읽으면 오늘이 아니라 그 글의 날짜 칸이 오른다 |
| 설정 | **`config.json`에 `trends_items` · `trends_reads` 두 키.** 비어 있으면 "설정 없음" 이유 행 | AI 추천 | `hypothesis_ledger` · 회고와 같은 방식. 못 읽는 것과 0건이 구별된다 |
| 화면 | **좌측 메뉴 항목 하나 + 한 화면(오늘 3건 카드 위, 잔디 아래).** 화면은 응답만 보고 그린다. 응답 문자열은 `textContent`, 링크는 `http(s)`만 | AI 권장안(디자인 트랙에서 보드로 확정) | 디자인은 기존 `.claude/design/DESIGN.md` 토큰을 재사용한다. 잔디 색 4단계는 새 토큰이 필요한지 디자인 단계에서 본다 |

## 위험 (1순위부터)

1. **조용히 비어 보이기** — wiki가 파일을 안 쓴 날과 파일이 깨진 날이 같은 빈 화면이면 원인을 모른다. 이유 행을 네 가지로 구분한다(PRD 수용 조건 7)
2. **과거 칸이 바뀐다** — 지난 날 글을 읽으면 이미 본 잔디 칸이 달라진다. 의도한 동작이라 PRD에 적었다(Finn B)
3. **화면과 서버 필드 불일치** — 새 필드는 가짜 데이터로 서버를 띄워 브라우저에서 본다(`.claude/rules/non-obvious-patterns.md`)
4. **동시 쓰기** — 읽음 파일은 desk 하나만 쓰고(wiki는 동향 파일만), 잠금과 재확인으로 desk 안 동시성만 막는다
5. **두 파일의 독립** — 읽음 기록은 성공했는데 북마크 기록이 실패하는 경우(또는 반대)에 한쪽 상태가 다른 쪽을 바꾸면 안 된다. 화면 에러도 따로 보인다(PRD 수용 조건 18)
