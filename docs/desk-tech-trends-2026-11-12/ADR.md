# ADR: desk-tech-trends

> 번호는 아직 없다. 번호 발급은 지휘 규칙(CLAUDE.md)을 따라 확정 때 붙인다. 근거는 [PRD.md](PRD.md) · [ARCHITECTURE.md](ARCHITECTURE.md).

## ADR-(번호 미발급) 동향은 wiki가 파일로 주고 desk는 읽기만 한다

- 결정: desk는 인터넷에서 글을 가져오지 않는다. wiki가 JSON Lines 파일 하나(`trends_items`)에 쓰고 desk가 읽는다. 읽음은 desk가 별도 파일(`trends_reads`)에 쓴다. 두 파일은 서로 쓰지 않는다
- 이유: 회고 우편함과 같은 방식이라 읽기·쓰기 규칙을 재사용한다. desk가 외부 호출과 요약 만들기를 안 맡고, 외부 패키지를 들이지 않는 규칙을 지킨다(모델 토큰도 안 쓴다)
- 대안: desk가 직접 가져옴(wiki와 안 엮이지만 외부 호출·요약을 desk가 맡게 되고 표준 라이브러리 규칙에 걸림)
- 결정 주체: Finn(A 선택, 이유 미기재)

## ADR-(번호 미발급) 잔디 칸은 글이 나온 날 기준 읽은 건수(0~3)이고 서버가 계산한다

- 결정: 글의 `date`로 묶어 읽은 distinct id 수를 3으로 잘라 칸 값으로 준다. 지난 날 글을 읽으면 그 글의 날짜 칸이 오른다. 같은 id 중복과 동향 파일에 없는 id는 세지 않는다. 기간은 1년, 오늘 기준은 서버
- 이유: "결국 읽은 게 중요하다"(Finn). 건수 그대로가 단순하다(Finn). 날짜별 글 건수(total)도 같이 준다(툴팁 「글 n건 중 m건 읽음」, AI 결정). 서버가 계산하면 화면이 계산을 안 해 숫자가 갈라지지 않는다
- 대안: 읽은 날 칸이 오름(과거 칸이 안 바뀌지만 3건 초과로 4단계가 깨짐), 비율(wiki가 2건 보낸 날도 최고 단계가 나오지만 같은 색이 날마다 다른 뜻)
- 결정 주체: Finn(칸 기준 B · 건수 A · 1년 A) / 중복·없는 id 제외는 AI 가정, 반려 가능

## ADR-(번호 미발급) 읽음은 `POST /trends/read`로 멱등하게 덧붙이고 취소는 없다

- 결정: 글 id 하나를 받아 읽음 줄 `{id, at}`을 덧붙인다. 잠그고 쓰기 직전 다시 읽어 이미 있으면 덧붙이지 않는다. 동향 파일에 없는 id는 거절한다. 토큰 헤더와 입력 검증은 `POST /pick`과 같다. 취소 줄은 두지 않는다
- 이유: GET은 읽기만 한다는 ADR-009를 지키면서 읽음을 파일에 남긴다. 멱등이라 두 탭이 동시에 눌러도 줄이 하나다. 취소는 필요 없다고 Finn이 판단했다
- 대안: 취소 가능(Finn이 불필요하다고 함), GET으로 읽음 처리(ADR-009 위반)
- 호출 시점: 화면이 원문 링크 클릭 때 보낸다(Finn, 2026-11-12). 쓰기가 실패해도 링크는 연다(Finn A)
- 결정 주체: Finn(취소 없음 B · 링크 클릭=읽음) / 멱등·잠금·거절은 AI 추천

## ADR-(번호 미발급) 북마크는 별도 이벤트 파일에 덧붙이고 마지막 줄이 이긴다

- 결정: 설정 키 `trends_marks`의 JSON Lines 파일에 `{id, on, at}` 줄을 덧붙인다. 글마다 마지막 줄이 현재 상태다. 켜기 · 끄기 모두 같은 POST(토큰 헤더 · 입력 검증은 `/pick`과 같고 잠금 후 재확인으로 멱등). 동향 파일에 없는 id는 거절. GET은 읽기만(ADR-009). 읽음 파일과 섞지 않는다
- 이유: 읽음은 취소가 없지만 북마크는 켜고 끄므로 규칙이 다르다. 줄 추가만으로 되돌릴 수 있어 파일을 고쳐 쓰지 않는다. 한 파일에 섞으면 읽음 건수 집계(잔디)가 북마크 줄을 걸러야 한다
- 대안: 읽음 파일에 종류 필드를 더해 섞기(파일은 하나지만 잔디 집계에 필터가 생김), 북마크 목록 파일을 통째로 다시 쓰기(동시 쓰기에 약함)
- 결정 주체: Finn(북마크 기능 · 수동 해제 · 목록 모양) / 저장 방식은 AI 가정, 반려 가능

## ADR-(번호 미발급) 경로는 `config.json`의 `trends_items` · `trends_reads` · `trends_marks` 세 키로 받는다

- 결정: 각각 파일 경로 하나. 비어 있으면 "설정 없음" 이유 행을 보인다. `trends_marks`가 비면 북마크 토글만 막히고 나머지는 그대로다
- 이유: 경로가 코드에 박히지 않고 위치가 바뀌면 설정 한 줄만 고친다. 못 읽는 것과 오늘 0건이 구별된다
- 대안: 코드에 경로 박기, 키 하나에 디렉터리(파일 이름 규칙을 desk가 가정함)
- 결정 주체: AI 가정, 반려 가능(회고의 같은 결정을 따름)
