# ADR: desk-kanban (초안)

> 번호는 혼자 발급하지 않는다(CLAUDE.md). 번호 미발급은 지휘 세션이 정한다. 기존 ADR 인용은 번호 옆 괄호 한 줄.

## ADR-(번호 미발급) 시작 요청은 카드와 별도 파일로 쓴다

- **상태**: 제안
- **맥락**: 서버(`/board/start`)와 `scripts/desk.py`(`board move`)가 같은 카드 JSON을 읽고 고쳐 쓰면, 나중에 쓴 쪽이 앞의 변경을 지운다. 원자적 쓰기(ADR-001, 임시 파일 + `os.replace`)는 읽는 쪽이 반쯤 쓴 파일을 못 보게 할 뿐 이런 덮어쓰기는 못 막는다.
- **결정**: 시작 요청은 `<id>.request.json`(`at` 포함)으로 따로 쓴다. 카드의 시작 요청 시각·「요청됨」 배지는 이 파일에서 계산한다. 쓰는 방식은 기존 `desk/atomic.py`를 그대로 쓴다(새 ADR 불필요).
- **결정 주체**: AI 보충(Finn 승인 전). Finn의 결정(요청 파일 방식, 카드 저장 위치)은 PRD 「결정」.
- **대안**: ① 카드 파일에 `requested_at` 필드를 넣고 파일 잠금 사용(복잡, 잠금 규약 신설) ② 그냥 마지막 쓰기가 이김(시작 요청이 사라질 수 있음).
- **결과**: 시작 경로의 충돌이 사라진다. 요청 파일이 카드와 따로 쌓이므로 카드 삭제·보관 때 요청 파일도 같이 정리해야 한다. 서버의 보관/되살리기와 `desk.py` 이동의 동시 실행은 그대로 남는다(`미측정: 겹치는 빈도`).

## ADR-(번호 미발급) 열 이동은 지휘 세션만, 순방향만 허용한다

- **상태**: 제안
- **맥락**: 완료는 PR merge이고 desk는 merge를 직접 못 본다(PRD). 열을 사람이 화면에서 옮기면 지휘 세션의 판단과 갈라진다.
- **결정**: 열 이동은 `scripts/desk.py board move`만 한다. 허용 전이는 `planned → doing → done`뿐이고 역방향·건너뛰기는 거절한다. PR 대기는 열이 아니라 `doing` 카드의 표시(`board pr`)이고 이것도 한 번만 적는다. 진입 시각은 이동·표시할 때 한 번 적는다.
- **결정 주체**: 이동 주체(지휘 세션)는 Finn. 순방향만 허용은 AI 판단(반려 가능).
- **대안**: 역방향도 허용(잘못 옮긴 걸 되돌리기 쉽다, 대신 시각 기록이 덮여 경과 일수가 틀어진다).
- **결과**: 잘못 옮기면 되돌리지 못하고 카드 파일을 직접 고치거나 새 카드를 만들어야 한다. 되돌림 수요가 생기면 그때 이 줄을 다시 본다.

## ADR-(번호 미발급) desk는 칸반에서 쓰기만 하고 프로세스는 실행하지 않는다

- **상태**: 제안
- **맥락**: 「작업 시작」 버튼이 오르카 세션을 만들려면 명령을 실행해야 한다. desk는 허용된 파일만 읽고(ADR-009 「새 탭은 허용 목록의 원장을 GET마다 읽기만 한다」) 사람의 행동은 서버가 표식 파일로 쓴다(ADR-011 「복습 끝·공유 끝 마킹은 서버가 쓴다」).
- **결정**: desk는 `board/<레포>/` 아래 카드·요청 파일만 쓰고 서브프로세스를 부르지 않는다. 세션 생성은 요청 파일을 읽는 지휘 세션이 한다.
- **결정 주체**: Finn (실행 주체 결정은 PRD 「결정」, 이유 미기재).
- **대안**: desk가 오르카를 직접 호출(버튼 하나가 명령 실행 경로가 되어 보안 경계가 넓어진다).
- **결과**: 지휘 세션이 꺼져 있으면 요청이 조용히 쌓이고 「요청됨」 배지만 남는다(PRD가 받아들인 한계).
