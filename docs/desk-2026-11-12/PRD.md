# PRD: desk 화면 재설계 구현 — 다크 톤 · 좌측 메뉴

## 무엇을

승인된 디자인(Better Stack 구조 + 다크 톤, Pretendard, 좌측 사이드메뉴)을 `page/index.html`에 구현한다. 새 기능·새 데이터는 없다. 예외는 메뉴 배지용 건수 하나(아래 결정).

- 디자인 정본: [`.claude/design/DESIGN.md`](../../.claude/design/DESIGN.md)(토큰·컴포넌트), [`brief.md`](../../.claude/design/brief.md)(화면·상태), 캔버스 `작업: 화면` 탭(`Screen1Track`~`Screen6Health`) · `Nav` · `Judge` · `States` · `Data` 보드
- 승인 기록: `checkpoints/01-design-system.md`, `checkpoints/02-screens.md` (둘 다 verdict 승인, 결정 주체 Finn)

## 왜

현행 화면은 라이트 톤이고 상단 탭 6개라 훑기 어렵다. 지휘 세션을 쓰는 동안 옆에 띄워 두는 화면이라, 어두운 바탕에서 상태(작업 중 · 승인 대기 · 막힘)가 점 + 라벨로 바로 읽혀야 한다.

| 지표 | 비포 | 목표 |
|---|---|---|
| 판정·복습 대기 건수를 알려면 | 탭을 열어 목록을 세야 한다 | 메뉴 배지로 탭을 열지 않고 본다 |
| 화면 6개 × 상태 6종(정상·로딩·빈·에러·config·missing) | 화면별로 제각각 | 브리프 상태 표대로 전부 존재 |
| 의미색 | 임의 | 5역할(선택·진행 / 사람 차례 / 정상 / 오류 / 중립)만, 색만으로 뜻을 전하지 않음 |

## 수용 조건

1. 상단 탭이 좌측 메뉴(펼침 264 / 접힘 64, 아이콘 + 툴팁)로 바뀐다. 3역량은 그룹 펼침이고 하위 선택 시 하위 항목만 올림면이다
2. 판정·복습함 메뉴에만 대기 건수가 붙는다(펼침 = 숫자, 접힘 = 점). 0건이면 숨긴다
3. 6개 화면이 캔버스 보드의 구조와 토큰을 따른다. 표는 muted 헤더 · 말줄임 · 행 구분선, 줄 맨 앞 상태 점 + 라벨
4. 기존 동작 보존: 판정 다시 고르기, 반영된 판정 잠금, 토큰 헤더, 보이는 탭만 폴링(ADR-010), 응답 문자열은 `textContent`로만
5. 외부 패키지 없음, 훅·서버가 모델에 글을 넣지 않음

## 결정

| 주제 | 결정 | 결정 주체 |
|---|---|---|
| 메뉴 배지 | 판정·복습함에만 숫자 배지. 이번 구현에 포함 | Finn |
| 배지가 세는 것 | 판정 = pick이 없는 카드 수, 복습 = `/review`의 items 수 | AI 제안(반려 가능) |
| 접힘 상태 배지 | 숫자 대신 주의색 점 | AI 제안(반려 가능) |
| 글꼴 | Pretendard를 레포에 포함(오프라인 동작). 라이선스는 SIL OFL 1.1이라 라이선스 전문 + 저작권 표기를 같이 둔다. 용량은 구현 때 재서 기록(`미측정`) | Finn(포함) / 라이선스 정정은 AI(원문 확인) |

## 비목표

새 데이터·새 화면, 폰 대응, 라이트 테마, 아이콘 레일, 도넛·히스토그램, 검색·기간 선택·Export, 판정 가설 게이트(별도 sdd 작업, 이슈 #1)
