# ADR: desk 화면 재설계 구현

> 번호는 임시다. 번호 발급은 지휘 규칙(CLAUDE.md)을 따라 확정 때 바꾼다.

## ADR-014(임시) 메뉴 배지 건수는 새 GET 하나가 준다

- 결정: `GET /nav-counts`가 `{judge, review}`를 준다. 클라이언트가 `/judgments`·`/review` 전체를 받아 세지 않는다
- 이유: 메뉴는 항상 보이는데 두 목록은 보이는 탭만 부른다(ADR-010). 배지를 위해 둘을 15초마다 통째로 받으면 보이는 탭만 부른다는 원칙이 깨진다. 건수만 주면 응답이 작다
- 대안: 클라이언트 집계(응답 큼, ADR-010 위반), 배지 없음(Finn이 포함으로 결정)
- 결정 주체: Finn(배지 포함) / AI 추천 수용(엔드포인트 형태 — 반려 가능)

## ADR-015(임시) 색·간격은 `:root` CSS 변수 한 곳, 컴포넌트는 직접 값을 쓰지 않는다

- 결정: DESIGN.md 토큰을 CSS 변수로 옮기고 컴포넌트는 변수만 쓴다
- 이유: 톤을 다시 바꿀 때 한 곳만 고치면 된다(2026-10 두 레포에서 톤 교체로 문서·구현을 다시 쓴 이력)
- 결정 주체: AI 추천 수용(반려 가능)

## ADR-016(임시) 폰트는 서버가 이름 하나만 열어 준다

- 결정: `page/fonts/PretendardVariable.woff2`를 `GET /fonts/PretendardVariable.woff2`로 준다. 허용 이름 외 요청은 404
- 이유: 오프라인 동작(Finn 결정: 레포에 포함)을 하려면 HTML 안 `@font-face`가 가리킬 주소가 필요하다. base64로 HTML에 넣으면 `/` 응답이 폰트 크기만큼 커지고 15초 폴링과 무관하게 매번 내려간다. 파일 서빙을 일반화(디렉터리 통째로)하면 경로 조작 면이 생겨 이름 하나만 연다
- 대안: base64 인라인(응답 비대), CDN(오프라인 폴백 실패)
- 결정 주체: AI 추천 수용(반려 가능)
