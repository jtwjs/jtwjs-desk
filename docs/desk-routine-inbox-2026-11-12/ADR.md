# ADR: desk-routine-inbox

> 번호는 아직 없다. 번호 발급은 지휘 규칙(CLAUDE.md)을 따라 확정 때 붙인다. 근거는 [PRD.md](PRD.md) · [ARCHITECTURE.md](ARCHITECTURE.md).

## ADR-(번호 미발급) 우편함은 JSON Lines 두 파일로 나누고, 같은 문항 id의 마지막 줄이 이긴다

- 결정: 질문함(wiki가 씀)과 답함(desk가 씀) 두 파일. 한 줄에 문항 또는 답 하나. 문항 id는 날짜를 포함한 해시이고 wiki가 만들어 질문함에 쓰며 desk는 그대로 답함에 옮긴다. 같은 id의 마지막 줄이 이긴다. 깨진 줄은 건너뛰고 개수를 표시한다(`desk-hypothesis-gate` 원장과 같은 읽기 규칙, 같은 파서를 쓸 수 있는지는 구현 때 확인)
- 이유: 서로 같은 파일에 쓰지 않아 동시 쓰기 충돌이 구조적으로 없다. 한 줄이 깨져도 나머지가 읽힌다. 답을 고치는 건 줄을 덧붙이는 것이라 읽기 규칙이 "마지막 줄" 하나로 끝난다
- 대안: 한 파일을 둘이 씀(충돌 위험), 파일 전체를 JSON 하나로(쓰는 중 읽으면 전체가 깨짐), 날짜 없는 해시(같은 문항이 다른 날 나오면 id 충돌)
- 결정 주체: Finn(JSON Lines · 파일 분리 · id 해시 · 마지막 줄이 이김) / 날짜 포함은 AI, 반려 가능

## ADR-(번호 미발급) 자동 건너뜀은 화면이 열릴 때 POST로 한 번 쓴다

- 결정: `POST /routine/rollover`가 지난 날짜의 문항 중 답 줄이 없는 것에만 건너뜀 줄을 덧붙인다. 쓰기는 잠그고 쓰기 직전 답함을 다시 읽으며, 같은 호출을 여러 번 해도 결과가 같다. GET은 읽기만 한다
- 이유: GET은 읽기만 한다는 ADR-009를 지키면서 건너뜀을 파일에 남겨 "쌓이지 않게"라는 이유를 지킨다. 마지막 줄이 이기는 규칙 때문에 답 뒤에 건너뜀이 덧붙으면 답이 지워진다
- 대안: GET이 읽다가 씀(ADR-009 위반), 읽을 때 계산만(기록이 남지 않음), ADR-009에 예외 신설(다른 GET도 쓰기 쉬워짐)
- 결정 주체: Finn(A1 선택, 이유 미기재) / AI 추천 수용

## ADR-(번호 미발급) 미답 배지는 `/nav-counts`에 합치고 항목별로 격리한다

- 결정: 응답에 `routine`을 추가한다. 오늘 미답만 센다. 질문함이 깨져도 판정·복습 숫자는 나오고 이 항목만 이유를 달아 낸다
- 이유: 메뉴와 건수는 같이 살고 같이 죽는 관계라 따로 받을 이유가 없다(Finn). 지금 `count_nav`는 한 항목이 예외를 내면 전체가 실패할 수 있어 항목별 격리를 더한다(AI)
- 대안: 별도 엔드포인트(요청이 하나 늘고 실패가 번지지 않음, 속도 차이 `미측정`)
- 결정 주체: Finn(합침) / 격리는 AI

## ADR-(번호 미발급) 경로는 `config.json`의 `routine_questions` · `routine_answers` 두 키로 받는다

- 결정: 각각 파일 경로 하나. 비어 있으면 "설정 없음" 이유 행을 보인다(`hypothesis_ledger`와 같은 방식)
- 이유: 경로가 코드에 박히지 않고 위치가 바뀌면 설정 한 줄만 고친다. 못 읽는 것과 문항 0건이 구별된다
- 대안: 코드에 경로 박기, 키 하나에 디렉터리(파일 이름 규칙을 desk가 가정함)
- 결정 주체: Finn(수락, 이유 미기재) / AI 추천 수용
