# PRD: desk-routine-inbox (초안)

> 별도 작업이다. `desk-hypothesis-gate`와 원장·화면을 섞지 않는다. 요청은 wiki 세션에서 왔고(질문함·답함 우편함 구상), 결정은 Finn이 한다.

## 사용 장면 (Finn, 날것)

매일 밤 회고처럼 연다. 문항은 필요한 것 위주로 최소한. 문항 수의 숫자는 `미측정`(첫 2주 쓰며 정함).

## 결정

| 주제 | 결정 | 결정 주체 | 이유 |
|---|---|---|---|
| 못 답한 날 | **건너뜀으로 기록해서 쌓이지 않게 한다**(B). "초반에는"이라는 단서가 있어, 쓰면서 바꿀 수 있다 | Finn | Finn: 쌓이는 건 심리적 피로를 준다. 초반에는 강제로 안 쌓이게 한다 |
| 건너뜀 찍는 시점 | **날이 바뀔 때 자동으로 건너뜀을 찍는다.** 미답 배지는 오늘 것만 센다 | AI 추천 수용 (Finn "자동으로 진행", 이유 미기재) | AI: 직접 누르게 하면 안 누른 날이 쌓여 "쌓이지 않게"라는 처음 이유가 깨진다. 실수로 못 답한 날도 건너뜀으로 남는 건 감수 |
| 문항 수를 누가 줄이나 | **desk는 wiki가 보낸 문항을 그대로 전부 보인다.** 상한·자르기를 desk에 두지 않는다. 최소한으로 보내는 책임은 보내는 쪽(wiki)에 둔다 | Finn ("desk는 단순하게 두는 게 좋다") | Finn: desk는 단순하게. AI 지적: wiki가 많이 보내면 Finn의 "최소한"이 깨진다. 문항 수가 실제로 늘면 그때 다시 정한다(`미측정`) |
| 우편함 파일 형식 | **JSON Lines(한 줄에 문항 또는 답 하나).** 줄을 덧붙이는 방식이라 쓰는 중에 읽어도 깨지는 건 한 줄뿐이다. 질문함과 답함 파일을 나누는지는 미정 | Finn (B 선택, 이유 미기재) / AI 보충 | AI: 한 줄이 깨져도 나머지가 읽힌다. `desk-hypothesis-gate`의 원장과 같은 읽기 규칙(깨진 줄은 건너뛰고 개수 표시)을 재사용할 수 있다(미확인: 같은 파서를 쓸 수 있는지는 구현 때 본다). 문항을 고치려면 줄을 새로 써야 하는 건 감수 |
| 질문함·답함 파일 | **파일 둘로 나눈다.** wiki는 질문함만 쓰고 desk는 답함만 쓴다. 문항과 답은 문항 id로 잇는다 | Finn | Finn: 충돌 위험을 안고 가는 것보다 나누는 게 구조적으로 맞다. AI 보충: 서로 같은 파일에 쓰지 않아 동시 쓰기 충돌이 구조적으로 없다. 대신 문항 id가 두 파일을 잇는 유일한 끈이라 id 규칙이 중요해진다 |
| 문항 id | **문항 내용에서 만든 해시.** 사람이 읽거나 외울 필요 없다. 해시에 **날짜를 포함**해 같은 문항이 다른 날 다시 나와도 id가 달라지게 한다(AI 추가, 반려 가능). id는 wiki가 만들어 질문함에 쓰고, desk는 그 값을 그대로 답함에 옮긴다. 해시 알고리즘·입력 필드는 구현 때 정한다 | Finn (B 선택) / 날짜 포함은 AI | Finn: id는 항목을 구분하기만 하면 되고 꼬일 일이 가장 적은 쪽. AI 지적: 문항 텍스트를 고치면 id가 바뀌어 이미 쓴 답과 끊긴다. 같은 문항이 날마다 나오면 날짜 없이는 id가 겹친다 |
| 답을 바꿀 때 | **같은 문항 id의 마지막 줄이 이긴다.** 옛 줄은 파일에 남지만 읽을 때 무시한다. 답을 고쳐 쓰는 건 줄을 덧붙이는 것이다 | Finn (A 선택, 이유 미기재) / AI 보충 | AI: 오타를 고칠 수 있고 읽기 규칙이 "마지막 줄" 하나로 끝난다. 바꾸기 전 답은 화면에 안 보이는 건 감수 |
| 자동 건너뜀과 답의 순서 | **답이 있는 문항에는 건너뜀을 찍지 않는다.** 날이 바뀔 때 건너뜀은 아직 답 줄이 없는 문항에만 덧붙인다 | AI 제안 / Finn 수락("좋아 넣어줘") | AI: 마지막 줄이 이기는 규칙 때문에, 답 뒤에 건너뜀이 덧붙으면 답이 지워진다 |
| 파일 경로 설정 | **`config.json`에 키 둘: `routine_questions`(질문함) · `routine_answers`(답함).** 각각 파일 경로 하나. 비어 있으면 "설정 없음" 이유 행(`desk-hypothesis-gate`의 `hypothesis_ledger`와 같은 방식) | AI 추천 수용 (Finn "좋아", 이유 미기재) | AI: 경로가 코드에 박히지 않고 위치가 바뀌면 설정 한 줄만 고친다. 못 읽는 것과 문항 0건이 구별된다 |
