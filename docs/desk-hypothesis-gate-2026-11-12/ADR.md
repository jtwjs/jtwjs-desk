# ADR: desk-hypothesis-gate

> 번호는 아직 없다. 번호 발급은 지휘 규칙(CLAUDE.md)을 따라 확정 때 붙인다. 근거는 [PRD.md](PRD.md) · [ARCHITECTURE.md](ARCHITECTURE.md).

## ADR-(번호 미발급) 신호는 서버 `desk/`의 순수 함수가 계산하고 화면은 그리기만 한다

- 결정: 영역별 건수·적중, 가설 먼저 비율, 이유 없이 수락 비율을 `desk/`의 순수 함수가 계산한다. 화면은 받은 숫자를 그린다
- 이유: 계산이 한곳에 있어야 화면과 서버가 다른 숫자를 보이지 않는다. 새 필드는 서버·파서·화면을 각각 통과해도 이어 붙인 곳에서 깨진다(2026-11-12 회색 배지 사고, `non-obvious-patterns`). 새 필드는 가짜 데이터로 서버를 띄워 브라우저에서 한 번 본다
- 대안: 화면(JS)에서 계산(복사본 두 곳, 위 사고 재발)
- 결정 주체: Finn(서버 계산, 이유 미기재) / AI 지적 반영

## ADR-(번호 미발급) 신호는 새 엔드포인트(가칭 `/hypothesis-signal`)로 따로 준다

- 결정: 풀스택 탭이 열릴 때 기존 카드 응답과 병렬로 부른다. 이름은 구현 때 확정한다
- 이유: 카드(레포 `_learn/inbox.md`)와 신호(홈 원장)는 출처가 다른 독립 데이터다. 합치면 한쪽이 실패할 때 다른 쪽도 같이 빈다. 따로 두면 실패가 번지지 않고 병렬로 부르고 테스트가 쉽다. 속도 이점은 `미측정`
- 대안: 기존 카드 응답에 합치기(연쇄 실패)
- 결정 주체: Finn

## ADR-(번호 미발급) 원장 경로는 `config.json`의 `hypothesis_ledger` 키 하나로 받는다

- 결정: 값은 파일 경로 하나다. 비어 있으면 "설정 없음" 이유 행을 보인다. 경로 없음 / 파일 없음 / 형식 확인 필요는 기존 `missing_row` 패턴을 따른다. 기록 0건이어도 띠를 숨기지 않는다(ADR-008 패턴)
- 이유: 읽을 파일이 한 곳으로 정해지고, 위치가 바뀌면 설정 한 줄만 고친다. 못 읽는 것과 기록이 0건인 것이 구별돼야 8주 뒤 비포 비교가 틀어지지 않는다
- 대안: 코드에 경로 박기(개인 홈 경로가 코드에 남음), 여러 파일 키(영역별 파일 없음, 필요 없음)
- 결정 주체: Finn(키 이름 수락, 이유 미기재) / AI 추천 수용

## ADR-(번호 미발급) 깨진 원장 줄은 건너뛰고 개수와 수정 후보만 보인다

- 결정: 깨진 줄만 건너뛰고 건너뛴 개수를 띠에 표시한다. 줄마다 줄 번호·이유·(값이 하나로 정해질 때만) 수정 후보를 보인다. desk는 이 줄을 고쳐 쓰지 않는다
- 이유: 한 줄 때문에 전체를 버리면 나머지 기록까지 안 보인다. 개수를 알려야 숫자가 실제보다 낮을 수 있음을 안다. 원장은 sdd도 쓰는 파일이라 desk가 줄을 고치면 동시 쓰기로 또 깨질 수 있다. 입력을 어디에 저장할지는 별도 결정이다
- 대안: 파일 전체 거부(기록 안 보임), desk가 자동 수정(동시 쓰기 위험)
- 결정 주체: Finn(건너뛰기 + 수정 제안 요청) / "자동 수정"을 "제안 표시"로 좁힌 해석은 AI — 반려 가능
