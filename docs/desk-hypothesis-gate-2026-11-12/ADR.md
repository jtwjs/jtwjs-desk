# ADR: desk-hypothesis-gate

> 번호는 아직 없다. 번호 발급은 지휘 규칙(CLAUDE.md)을 따라 확정 때 붙인다. 근거는 [PRD.md](PRD.md) · [ARCHITECTURE.md](ARCHITECTURE.md).

## ADR-(번호 미발급) 신호는 서버 `desk/`의 순수 함수가 계산하고 화면은 그리기만 한다

- 결정: 영역별 건수·적중, 가설 먼저 비율, 이유 없이 수락 비율, 연속 건수·건너뜀 건수(2026-11-13 추가)를 `desk/`의 순수 함수가 계산한다. 화면은 받은 숫자를 그린다
- 이유: 계산이 한곳에 있어야 화면과 서버가 다른 숫자를 보이지 않는다. 새 필드는 서버·파서·화면을 각각 통과해도 이어 붙인 곳에서 깨진다(2026-11-12 회색 배지 사고, `non-obvious-patterns`). 새 필드는 가짜 데이터로 서버를 띄워 브라우저에서 한 번 본다
- 대안: 화면(JS)에서 계산(복사본 두 곳, 위 사고 재발)
- 결정 주체: Finn(서버 계산, 이유 미기재) / AI 지적 반영

## ADR-(번호 미발급) 신호는 새 엔드포인트(가칭 `/hypothesis-signal`)로 따로 준다

- 결정: 풀스택 탭이 열릴 때 기존 카드 응답과 병렬로 부른다. 이름은 구현 때 확정한다
- 이유: 카드(레포 `_learn/inbox.md`)와 신호(홈 원장)는 출처가 다른 독립 데이터다. 합치면 한쪽이 실패할 때 다른 쪽도 같이 빈다. 따로 두면 실패가 번지지 않고 병렬로 부르고 테스트가 쉽다. 속도 이점은 `미측정`
- 대안: 기존 카드 응답에 합치기(연쇄 실패)
- 결정 주체: Finn

## ADR-(번호 미발급) 원장 경로는 `config.json`의 `hypothesis_ledger` 키 하나로 받는다

- 결정: 값은 파일 경로 하나다. 비어 있으면 "설정 없음" 이유 행을 보인다. 경로 없음 / 파일 없음 / 형식 확인 필요는 기존 `missing_row` 패턴을 따른다. 기록 0건이어도 띠를 숨기지 않는다(ADR-008 패턴)
- 이유: 읽을 파일이 한 곳으로 정해지고, 위치가 바뀌면 설정 한 줄만 고친다. 못 읽는 것과 기록이 0건인 것이 구별돼야 8주 뒤 비포 비교가 틀어지지 않는다
- 대안: 코드에 경로 박기(개인 홈 경로가 코드에 남음), 여러 파일 키(영역별 파일 없음, 필요 없음)
- 결정 주체: Finn(키 이름 수락, 이유 미기재) / AI 추천 수용

## ADR-(번호 미발급) 깨진 원장 줄은 건너뛰고 개수와 수정 후보만 보인다

- 결정: 깨진 줄만 건너뛰고 건너뛴 개수를 띠에 표시한다. 줄마다 줄 번호·이유·(값이 하나로 정해질 때만) 수정 후보를 보인다. desk는 이 줄을 고쳐 쓰지 않는다
- 이유: 한 줄 때문에 전체를 버리면 나머지 기록까지 안 보인다. 개수를 알려야 숫자가 실제보다 낮을 수 있음을 안다. 원장은 sdd도 쓰는 파일이라 desk가 줄을 고치면 동시 쓰기로 또 깨질 수 있다. desk 입력은 2026-11-13에 되돌려 desk는 읽기 전용이다(아래 ADR)
- 대안: 파일 전체 거부(기록 안 보임), desk가 자동 수정(동시 쓰기 위험)
- 결정 주체: Finn(건너뛰기 + 수정 제안 요청) / "자동 수정"을 "제안 표시"로 좁힌 해석은 AI — 반려 가능

## ADR-(번호 미발급) desk는 이 기능에서 읽기 전용이다

- 결정: 원장도 입력 파일도 desk가 쓰지 않는다. 쓰기 엔드포인트를 만들지 않는다. 가설·수락·이유 입력은 맡기는 순간의 sdd 흐름에서만 일어난다
- 이유: desk에서 받은 가설은 맡긴 뒤의 사후 입력이라 AI 반박이 없어 리셋 조건(가설 + 반박)과 충돌하고, '가설 먼저' 비율을 부풀린다. 원장 쓰는 쪽이 하나여서 동시 쓰기도 없다
- 대안: desk 입력 허용(2026-11-12 변경, 번복), desk 전용 입력 파일
- 결정 주체: Finn(번복, 이유 미기재). 위 충돌은 번복 전에 AI가 지적했다

## ADR-(번호 미발급) 연속은 desk가 같은 작업 식별 줄에서 계산하고, 줄 단위는 쓰는 쪽(sdd)이 정한다

- 결정: desk는 같은 작업 식별이 붙은 줄을 원장 순서대로 읽어 연속·건너뜀을 센다. 식별이 없는 줄은 연속에서 뺀다. 연속 값은 이유를 쓴 줄에서 0이 되고, 가설 재요구 상태는 연속이 기준에 닿으면 켜져 가설 + 반박 줄에서 꺼진다(값과 상태를 따로 계산, 결정 주체 Finn, AI 추천 수용 2026-11-13). 줄을 모든 맡김에 남길지, 어떻게 판정할지는 sdd 쪽 작업이 정한다
- 이유: 쓰는 쪽 단위가 미정이어도 desk는 같은 규칙으로 계산하고, sdd 완성을 기다리지 않고 가짜 원장으로 먼저 만들 수 있다. 쓰는 쪽이 게이트 종류에서만 줄을 남기면 연속 신호가 약해진다(추정)
- 대안: desk가 맡김을 직접 관찰(훅이 desk에 없고 토큰 0 원칙에 걸림)
- 결정 주체: AI 가정, Finn 확인 전 — 반려 가능
- 추가(2026-11-13, sdd 쪽 확정을 따름): 한 작업은 `(repo, task)` 쌍이다. 재요구 꺼짐은 켜진 뒤 같은 작업에서 `hyp=true` 줄과 `rebut=true` 줄이 순서 무관으로 모이면 둘째 줄에서 일어난다. 적중은 별도 추가 줄(`ref`로 원 줄 연결, 같은 `ref`는 마지막 줄)이라 desk가 합쳐 센다. 결정 주체: sdd 쪽 확정(Finn 결정, 그쪽 메시지 기준)이고 desk는 따른다
- 추가(2026-11-13): '이유 없이 수락' 비율은 `gate=null` 줄을 분모·분자에서 뺀다. 연속 계산이 `gate=null`을 빼는 것과 기준을 맞춰 두 값이 어긋나지 않게 한다. 대안은 모든 추천을 세기(비설계 선택지의 수락이 비율을 올림). 결정 주체: Finn(이유 미기재)
- 추가(2026-11-13): '가설 먼저' 비율의 분모는 `gate`·`hyp`·`rec` 중 하나라도 채워진 "의미 있는 줄"이다. 줄이 프롬프트마다 쌓이면 모든 줄을 분모로 쓰는 값이 짧은 입력에 부풀기 때문이다. 대안은 게이트 줄만(모델이 쓴 `gate`에 전부 의존), 쓰는 쪽이 줄을 덜 남김(줄 단위가 sdd 쪽 결정이고 안 남긴 줄은 건너뜀으로도 안 잡힘). 결정 주체: Finn(이유 미기재)
