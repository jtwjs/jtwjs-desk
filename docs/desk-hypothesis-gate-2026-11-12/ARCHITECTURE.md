# ARCHITECTURE: desk-hypothesis-gate

> 결정 근거는 [PRD.md](PRD.md)의 「결정」 절. 이 문서는 구조 결정을 하나씩 채운다. 현재 코드의 의존 방향(`scripts/` · `hooks/` · `page/` → `desk/`, 셋은 서로 import하지 않음)을 그대로 따른다.

## 결정

| 주제 | 결정 | 결정 주체 | 이유 |
|---|---|---|---|
| 신호 계산 위치 | **서버 쪽 `desk/`의 순수 함수**가 영역별 건수·적중을 계산하고, 화면은 받은 숫자를 그리기만 한다 | Finn (스스로 선택, 이유 미기재) | AI 지적: 새 필드는 서버·파서·화면 연결을 따로 통과해도 이어 붙인 곳에서 깨진다(2026-11-12 회색 배지 사고, non-obvious-patterns). 새 필드는 가짜 데이터로 서버를 띄워 브라우저에서 한 번 본다 |
| 원장 없음·깨짐 표시 | **기존 화면처럼 이유를 적은 행으로 남긴다**(경로 없음 / 파일 없음 / 형식 확인 필요, `missing_row` 패턴). 기록 0건이어도 띠를 숨기지 않는다 | Finn | Finn: 내가 헷갈리지 않게, 다른 화면과 일관성 있게. AI: 숨기면 "기록이 없는 건지 못 읽는 건지" 구별이 안 된다 |
| 신호 엔드포인트 | **새 엔드포인트(가칭 `/hypothesis-signal`)로 따로 둔다.** 풀스택 탭이 열릴 때 기존 카드 응답과 병렬로 부른다. 이름은 구현 때 확정 | Finn | Finn: 서로 연관 있어도 독립된 데이터면 분리한다(연쇄 실패 방지·병렬 호출·테스트 쉬움). AI: 카드(레포 `_learn/inbox.md`)와 신호(홈 원장)는 출처가 달라 독립이 맞다. 속도 이점은 로컬 서버라 작을 수 있고 `미측정`, 근거는 실패 격리와 테스트 분리 |
| 원장 줄이 깨졌을 때 | **깨진 줄만 건너뛰고 건너뛴 개수를 띠에 표시한다.** 깨진 줄마다 줄 번호·이유·(고칠 값이 하나로 정해질 때만) 수정 후보를 보여준다. **desk는 원장을 고치지 않는다**: 수정은 Finn이 직접 한다. 이슈 결정 6의 읽기 전용은 2026-11-12에 풀렸지만(입력 허용), 원장은 sdd도 쓰는 파일이라 desk가 줄을 고치면 동시 쓰기로 또 깨질 수 있어 "자동 수정" 적용은 이번 범위 밖(입력을 어디에 쓸지는 별도 결정) | Finn (건너뛰기 + 자동수정 제안 요청, "크리티컬한 이슈는 아님"). 자동 수정을 "제안 표시"로 좁힌 해석은 AI | Finn: 치명적이지 않다. AI: 깨진 줄이 있어도 나머지 기록으로 신호를 보여주고, 숫자가 실제보다 낮을 수 있음을 개수로 알린다 |
| 원장 경로 설정 키 | **`config.json`의 `hypothesis_ledger` 키 하나(파일 경로).** 비어 있으면 "설정 없음" 이유 행. 그 밖의 읽기 실패는 기존 세 이유(경로 없음 / 파일 없음 / 형식 확인 필요)로 보인다 | Finn (이름 수락, 이유 미기재) / AI 추천 수용 | AI: 읽을 파일이 한 곳이고 위치가 바뀌면 설정 한 줄만 고친다. 못 읽는 것과 기록 0건이 구별돼야 비포가 틀어지지 않는다 |
