# 디자인 브리프: desk 화면 재설계

> 상태: **초안 — Finn 검토 대기** · 2026-11-11 · 이 문서는 내용만 적는다. 색 · 서체 · 치수는 `DESIGN.md`(다음 단계)에 쓴다.
> 입력: `docs/desk-2026-11-11/{PRD,ARCHITECTURE,ADR}.md` · 레퍼런스 기록 `.claude/design/references/README.md`
> 승인 전에는 캔버스를 그리지 않는다(`design-brief` §5).

## 1. 화면 목적

지휘 세션으로 여러 작업을 돌리는 Finn 한 명이, 로컬 페이지 하나에서 트랙 · 판정 · 복습 · 역량 · 주간 · 건강도를 훑고 필요할 때만 한두 번 눌러 처리한다. 진입은 브라우저 탭 고정과 ntfy 알림이다.

지금 화면이 마음에 들지 않는다는 것이 이 재설계의 출발이다. 기준은 **Better Stack의 UI/UX 구조와 다크 톤**이고, **요소 수는 그만큼 늘리지 않는다**(아래 「복잡도 원칙」).

## 2. 화면 / 뷰포트

데스크톱 우선. 폰은 범위 밖이다(알림만, 기존 `desk-phone-scope` 결정).

| 화면 | 한 문장 목적 | 데이터 | 쓰기 |
|---|---|---|---|
| 트랙 | 지금 도는 세션들의 상태를 훑는다 | `GET /sessions` | 없음 |
| 판정 | 지휘가 올린 질문에 고르거나 직접 쓴다 | `GET /judgments` | `POST /pick` |
| 복습함 | 건너뛴 이해증명과 이관 안 된 학습 카드를 복습한다 | `GET /review` | `POST /review/done` |
| 3역량 · AI워크플로우 | 반복되는 패턴을 횟수순으로 본다 | `GET /competency/workflow` | 없음 |
| 3역량 · 적극성 | 기준 메모, 소요시간, 임팩트 링크, 미반영 공유 파일 | `GET /competency/proactive` | `POST /share/shared` |
| 3역량 · 풀스택 | 영역별 학습 카드를 복습 순서로 본다 | `GET /competency/fullstack` | 없음 |
| 주간 롤업 | 지난 7일 합계와 레포별 진행을 본다 | `GET /weekly` | 없음 |
| 레포 건강도 | 레포별 AI 준비도 점수와 경과일을 본다 | `GET /repo-health` | 없음 |

화면 6개(트랙 · 판정 · 복습함 · 3역량 · 주간 롤업 · 레포 건강도). 3역량은 서브 화면 3개를 가진다.

## 3. 권한

사용자는 Finn 한 명이고 화면은 로컬(127.0.0.1)에서만 열린다. 읽기 화면은 조건이 없고, 쓰기 버튼은 페이지 토큰 · Origin · Host 검사를 통과해야 저장된다(ADR-004). 역할별로 달라지는 화면은 없다. **반영된 판정은 잠긴다** — 다시 고를 수 없다(PRD `desk-repick`).

## 4. 상태

화면 단위로 적는다. **조용히 비어 보이는 화면이 없어야 한다** — ARCHITECTURE가 이 확장의 1순위 위험으로 꼽은 것이다. "제안"은 이 브리프가 처음 정한 것이고 검토에서 Finn이 확정한다.

| 화면 | 정상 | 로딩 | 빈 | 에러 | config 한 줄 | missing 행 |
|---|---|---|---|---|---|---|
| 트랙 | 세션 행: 레포 · 브랜치 · 상태 점 + 라벨 · 마지막 신호. 승인 대기가 위 | 첫 응답 전 표 아래 한 줄 대기 문구 | "지금 도는 세션 없음" 안내 | 요청 실패 한 줄 + 마지막 정상 목록 유지(제안) | 해당 없음 | 해당 없음 |
| 판정 | 카드: 질문 · 이유 · 옵션(추천 표시) · AI가 정한 것 · 전제 열림 · 직접 쓰기. 카드 상태는 선택 전 / 선택됨 / 반영됨(잠금) | 위와 같음 | "대기 중인 판정 없음" 안내 | 저장 실패(토큰 · Origin · 이미 반영됨)는 **그 카드 안에** 사유 한 줄, 입력한 내용은 유지 | 해당 없음 | 해당 없음 |
| 복습함 | 표: 레포 · 종류(작업 / 카드) · 제목 · 상태 · 반영 버튼 | 위와 같음 | "복습할 것 없음" 안내 | 반영 실패는 그 행에 인라인 | 있음 | 레포마다 경로 없음 / 파일 없음 |
| 3역량 | 워크플로우: 표(패턴 · 종류 · 횟수 · 마지막), 3회 이상 강조, friction 행 포함 / 적극성: 기준 메모 → 스피드 → 임팩트 → 투명성(복사 · 공유함) / 풀스택: 영역별 섹션(FE · BE · infra · 도메인 · 미분류) | 위와 같음 | 서브 화면마다 안내. 적극성은 "공유 파일 없음" · "경로 미설정"을 구분해 보인다 | 위와 같음 | 있음 | 레포마다 경로 없음 / 파일 없음 / 형식 확인 필요 |
| 주간 롤업 | KPI 칸(세션 · 프로젝트 · 커밋 · 학습카드 · 막힌 것) + **증감 슬롯**(직전 7일 기록이 있을 때만 보이고, 없으면 자리째 숨긴다) + 레포별 표 | 위와 같음 | 7일 모두 기록 없음이면 "일간 기록 없음" + 없는 날짜 목록 | 위와 같음 | 있음 | 없는 날을 날짜로 나열 |
| 레포 건강도 | 레포마다 점수 · 등급 · "n일 전 채점" 카드 | 위와 같음 | 설정된 레포가 없으면 안내 | 위와 같음 | 있음 | 경로 없음 / 채점 없음 / 형식 확인 필요 |

- **긴 텍스트**: 행을 여러 줄로 이어 보인다(Live tail처럼, Finn 결정). 열 이름만 말줄임. 한 행의 줄 수 상한은 `DESIGN.md`에서 정한다
- **config 한 줄** 문구: 폴백 사용 중 / 설정 없음 / 미등록 레포 n개와 이름 / 설정 오류 사유. 화면 맨 위, 제목 아래
- 폴링으로 갱신될 때 **입력 중인 내용 · 펼침 상태 · 스크롤 위치가 사라지면 안 된다**

## 5. 데이터

- 읽기 화면은 보이는 탭만 열 때 한 번, 열려 있는 동안 15초마다 요청한다(ADR-010). 숨은 탭은 요청하지 않는다
- 서버는 원장 파일을 요청 때마다 읽어 응답한다. 화면은 정렬 · 파싱 · 판단을 하지 않고 받은 순서대로 그린다
- 응답 문자열은 원장 파일의 임의 텍스트다. 화면에 넣을 때 마크업으로 해석하지 않는다(저장형 XSS 방지)
- 지금 서버는 최근 7일 합계만 준다. 증감은 서버가 아직 주지 않아서 **화면에는 슬롯(자리)만 설계하고 구현은 후속**이다(「후속」 참고). 주간 KPI가 무엇을 세는지는 「주간 KPI 규칙」

## 6. 폼 · 쓰기

| 동작 | 위치 | 결과 | 비활성 조건 |
|---|---|---|---|
| 판정 선택 / 직접 쓰기 + 메모(이유 · 범위 · 새 것 중 하나) | 판정 카드 | 선택 저장, 다시 고르기 가능 | 반영된 판정은 잠김 |
| 복습 반영 | 복습함 행 | 행이 목록에서 사라짐 | 요청 중 |
| 공유함 표시 | 적극성 · 투명성 항목 | 항목이 목록에서 사라짐 | 요청 중 |
| 복사 | 적극성 · 투명성 항목 | 클립보드로 복사하고 짧게 확인 표시 | 없음 |

에러는 해당 행/카드 안에 인라인으로 보인다(전역 토스트로 흩지 않는다). 입력한 내용은 실패해도 유지한다.

## 7. 반응형

데스크톱 우선. 폭이 좁아지면 메뉴를 접는다(미결: 접는 폭과 접힌 모습). 폰 대응은 하지 않는다.

## 8. 인터랙션

- 좌측 메뉴: 항목 선택 시 해당 화면, 3역량은 **그룹 펼침**(부모 항목 아래 하위 3개가 들여써서 나온다). 현재 위치가 메뉴에서 항상 보인다. 메뉴 접기 버튼이 있다
- 키보드: 메뉴 항목 · 버튼 · 입력 모두 Tab으로 닿고 포커스가 보인다
- 표: 말줄임된 열 이름 hover 시 전체 이름
- 복사 · 반영 · 공유함은 성공 시 짧은 확인 표시
- 모션은 최소(펼침 · 접힘 정도). 구체 사양은 `DESIGN.md`

## 9. 요소 매핑 제안

Better Stack 구성에서 가져오되 「복잡도 원칙」으로 줄인 것이다. 확정이 아니다.

| desk 요소 | Better Stack에서 따르는 것 |
|---|---|
| 화면 틀 | 좌측 메뉴 패널 + 본문. 화면마다 제목 + 한 줄 설명 |
| 메뉴 | 아이콘 + 라벨 항목, 선택 항목은 한 단계 밝은 면, 3역량 그룹 펼침과 접기 버튼 |
| 필터 | 칩 행(`라벨 \| 값`), 레포 선택이 필요한 화면(트랙 · 복습함 · 워크플로우 · 풀스택)에만 한 줄 |
| 목록 | 조밀한 표: muted 헤더, 열 이름 말줄임, 여러 줄 행, 행 구분선, 줄 맨 앞 상태 점 + 라벨 |
| 판정 | 카드: 옵션 선택 · 직접 쓰기 · 반영 잠금 |
| 주간 롤업 | KPI 칸 + 증감 슬롯(데이터 있을 때만) + 레포별 표. 아래 「주간 KPI 규칙」 |
| 레포 건강도 | 점수 + 등급 카드 |
| 안내 | `config` 한 줄은 제목 아래, `missing` 행은 빈 상태 카드, 로딩은 표 아래 한 줄 대기 문구 |

### 복잡도 원칙 (Finn 결정)

Better Stack은 메뉴가 많고 보고서가 수십 개인 앱이다. desk는 화면 6개 · 사용자 1명이다. **패턴은 따르고 요소 수는 줄인다.** 제안이며 검토에서 정한다. 숫자 상한은 눈대중으로 쓰지 않는다(`미측정`).

| 가져온다 | 가져오지 않는다 |
|---|---|
| 좌측 메뉴 패널, 그룹 펼침, 접기 버튼 | 아이콘 레일 · 둘째 컬럼 서브 내비 |
| 화면 제목 + 한 줄 설명 | breadcrumb · 기간 선택 · Export |
| 필터 칩 행(필요한 화면만, 한 줄) | 검색창 · 프리셋 · 시간 범위 · 저장/설정 아이콘 버튼 |
| 조밀한 표 + 상태 점 + 라벨 | 도넛 · 히스토그램 차트 |
| KPI 칸 + 증감 슬롯(주간 롤업만) | 우하단 채팅 · 사용자 아바타 · 브랜드 요소 |
| 표 아래 한 줄 상태 문구 · hover 툴팁 | 필터를 여러 줄로 쌓는 구성 |
| 고정폭은 ID · 경로 · 브랜치에만 | 본문 전체를 고정폭으로 |

### 주간 KPI 규칙 (제안)

**숫자는 Finn이 원본에서 다시 세어 볼 수 있어야 한다.** KPI 라벨 옆에 정의 보기(마우스를 올리면 "무엇을 세는지 + 직접 확인하는 법")를 둔다. KPI 묶음의 제목은 **"활동량"**이다 — 이해도 지표가 아니라는 것을 화면에서 드러낸다.

| KPI | 세는 것 | 한계 |
|---|---|---|
| 세션 | 그날 Finn이 직접 친 프롬프트가 있는 세션 기록 수(헤드리스 제외) | 병렬로 쪼갠 정도에 가깝다. 많다고 일을 많이 한 게 아니다 |
| 프로젝트 | 그날 세션이 있었던 레포 수(7일 동안 서로 다른 레포) | 세션이 없던 레포는 안 센다 |
| 커밋 | 세션이 있었던 레포에서 내 이메일로 쓴 머지 아닌 커밋 | **러너가 에이전트로 만든 커밋도 센다.** 한 phase가 한꺼번에 올리면 부푼다 |
| 학습카드 | 등록된 레포의 `_learn/inbox.md`에서 그날 날짜인 카드 수 | AI가 쓴 카드 수이고 이해했다는 신호가 아니다 |
| 막힌 것 | **주의 마지막 기록 시점에 남아 있는** error · blocked step + 그날의 막힌 질문 카드 | 7일 합이 아니다. 합하면 안 풀린 막힘을 매일 센다 |

증감 규칙:

- 비교는 **직전 7일 대비**(최근 7일 롤링)이고 달력 주가 아니다
- **절대 증감만**(예: +2). 퍼센트는 표본이 작아 쓰지 않는다
- **좋고 나쁨을 색으로 칠하지 않는다.** 방향 기호 + 숫자는 중립 역할이고, **막힌 것이 늘면 "사람 차례 · 주의" 역할**을 쓴다
- 막힌 것의 증감은 "주 마지막 기록 시점 개수의 차"다(합의 차가 아니다)
- **직전 7일 기록이 하나도 없으면 증감 슬롯을 자리째 숨긴다.** 빈 칸이나 "—"를 상시 노출하지 않는다(PRD `desk-no-new-collectors`가 짚은 빈 칸 함정)

## 10. 상태 의미 역할

색 값은 `DESIGN.md`에서 정한다. 여기서는 **역할과 desk 상태의 매핑**만 둔다. 색만으로 뜻을 전하지 않는다 — 항상 한국어 라벨과 점/모양을 같이 둔다. 한 줄(행)에는 의미 역할 하나만 쓴다.

| 의미 역할 | 쓰는 desk 상태 |
|---|---|
| 선택 · 진행 | 작업 중 · 현재 메뉴 · 선택한 옵션 · 링크 · 포커스 · 설명 들음 |
| 사람 차례 · 주의 | 승인 대기 · 판정 미선택 · 복습 대기 · 모름 · 신호 없음 · 3회 이상 강조 · 형식 확인 필요 · 전제 열림 |
| 정상 · 완료 | 반영됨 · 내 말로 설명 가능 · 정상 채점 |
| 오류 · 막힘 | 에러 · 막힌 step |
| 중립 · 비활성 | 입력 대기 · 잠금 · 경로 없음 · 파일 없음 · 채점 없음 |

참고: 이전 제안은 "파랑 = 사람 차례"였으나, Better Stack에서는 브랜드 인디고가 이미 선택 · 활성이라 뜻이 겹쳐서 사람 차례를 별도 역할로 분리했다.

## 11. 재사용 후보

디자인 시스템이 없다. 현행 토큰은 `page/index.html` 상단 CSS 변수(배경 · 패널 · 글자 · 흐림 · 테두리 · 강조 · 경고 · 위험 · 잠금)뿐이고 전부 라이트라 **교체 대상**이다. 컴포넌트 이름 참고는 Mobbin 문서(`ex-app-shell-row` · `ex-data-table-cell` · `ex-empty-state-card` · `ex-toast`)다.

## 12. 제약

- 외부 패키지 없음. Python 표준 라이브러리 + 정적 단일 페이지(CLAUDE.md)
- 서버 응답 문자열은 마크업으로 해석하지 않는다(저장형 XSS)
- 사람 이름 · vault 원문 · 세션 대화 원문을 화면 · 레포 · 상태 파일에 넣지 않는다(CRITICAL)
- 다크 바탕 위의 글자 대비를 확인한다. 올림면(선택 항목 · 입력 · 버튼) 위 작은 글자는 대비가 모자랄 수 있다
- 훅은 토큰을 쓰지 않는다. 화면 변경이 훅을 건드리지 않는다
