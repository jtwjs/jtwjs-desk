# 브리프: 풀스택 탭 신호 띠 (desk-hypothesis-gate)

> 상태: Finn 브리프 승인(2026-11-13). 결정 5개 기록 끝. 색·서체·치수는 쓰지 않는다(`DESIGN.md` 토큰 재사용). 근거는 `docs/desk-hypothesis-gate-2026-11-12/PRD.md` · `ARCHITECTURE.md`. 승인 전에는 캔버스를 그리지 않는다.

## 화면 목적

풀스택 탭 맨 위에서 가설 먼저 · 이유 없이 수락 · 연속 · 건너뜀 숫자와 영역별(FE · BE · infra · 도메인) 입력·적중 건수를 읽기 전용으로 보인다. 사용자는 Finn 한 명, 진입은 좌측 메뉴 3역량 > 풀스택.

## 화면 · 뷰포트

기존 풀스택 탭 위에 띠 하나를 더한다(새 메뉴 없음). 데스크톱만, 폰은 범위 밖. 쓰기 없음(PRD 「desk 역할」).

## 상태 (화면 단위)

| 상태 | 보이는 것 |
|---|---|
| 정상 | 위 구성 그대로 |
| 로딩 | 카드 틀을 먼저 그리고 값 자리에 `…`(결정 5). `—`는 이유 행이 있을 때만 쓴다 |
| 기록 0건 | 이유 행 없이 카드에 `0`을 그대로. 못 읽는 것과 구별된다 |
| 설정 없음 · 파일 없음 · 형식 확인 필요 | 카드 위에 이유 행 + 카드는 그대로 두고 값은 `—`(결정 2) |
| 신호 응답 실패(서버 오류) | 이유 행("신호를 불러오지 못함") + 값 `—`. 기존 풀스택 카드는 영향 없음(독립 엔드포인트, ADR). **AI 가정, 확인 전** |
| 깨진 줄 있음 | 카드 아래 주석에 건수(결정 3). 줄 번호·이유는 별도 보기에서(구현 때 정함, 미결) |
| 판정 전 · 식별 없는 줄 | 판정 전은 카드 안, 식별 없는 줄은 주석(결정 3) |
| 재요구 켜짐 | 연속 칸이 기준에 닿은 상태를 라벨로 표시(색만으로 전하지 않음). 기준 횟수는 Finn이 기준 기간 뒤 정함 |

- 기존 기능과의 관계: 확장(풀스택 탭에 띠 추가). 기존 카드·필터 칩 행 동작 보존

## 제약

- 외부 패키지 없음, 응답 문자열은 `textContent`로만(저장형 XSS)
- 색만으로 뜻을 전하지 않는다(라벨 + 점/모양 병기), 상태색 의미 역할은 `DESIGN.md`
- CRITICAL: 사람 이름 · vault 원문 · 세션 원문을 화면·상태 파일에 넣지 않는다
- 적중·가설 먼저·이유 없이 수락은 모델이 선언한 값이고 정확도가 미측정이라 참고값이다. 화면에 그렇게 표시할지는 구현 전 확인
