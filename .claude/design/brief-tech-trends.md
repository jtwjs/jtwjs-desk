# 디자인 브리프: 기술 동향 화면 (추가분)

> 상태: **승인(Finn, 2026-11-12, 미결 추천 수용)** · 2026-11-12 · 내용만 적는다(색 · 서체 · 치수는 `DESIGN.md`).
> 입력: `docs/desk-tech-trends-2026-11-12/{PRD,ARCHITECTURE,ADR}.md` · 기존 `brief.md`(6화면 재설계)와 `DESIGN.md`(스타일 정본)
> 기존 `brief.md`는 비목표에 "새 기능 · 새 데이터"를 두고 있다. 이 화면은 그 밖의 **새 기능**이라 파일을 나눠 쓴다(기존 문서는 고치지 않는다). 회고 화면(PR #7)도 `brief.md`에 없는 상태다.
> 승인 전에는 캔버스를 그리지 않는다(`design-brief` §5).

## 1. 화면 목적

Finn이 좌측 메뉴 「기술 동향」을 열자마자 **오늘 동향 3건(제목 · 짧은 요약 · 링크)**을 보고, 글마다 "읽음"을 눌러 기록한다. 아래 **잔디(1년)**는 날마다 그날 글을 몇 건 읽었는지(0~3)를 진하기로 보여 준다. 글은 wiki가 파일로 주고 desk는 보여 주기만 한다.

## 2. 화면 / 뷰포트

데스크톱만(폰은 범위 밖). 화면 하나: 위에 오늘 카드 3장, 그 아래 잔디. 한 화면에 둘 다 보인다(PRD 수용 조건 10).

| 요소 | 데이터 | 쓰기 |
|---|---|---|
| 오늘 카드 3장 | `GET /trends` 의 오늘 항목 | 읽음 버튼 → `POST /trends/read` |
| 잔디 1년 | `GET /trends` 의 날짜 → 건수(0~3) | 없음 |
| 하위 화면 「안 읽은 글」 | `GET /trends` 의 지난 미읽음 목록 | 같은 읽음 버튼 |

메뉴는 「기술 동향」 그룹이고 하위 항목 셋: **오늘**(카드 3장 + 잔디) · **안 읽은 글**(지난 날 글 목록) · **북마크**(담아 둔 글 목록, 필터 칩 전체 / 안 읽음 / 읽음). 3역량과 같은 그룹 펼침 방식이다(Finn 결정).

## 3. 권한

Finn 한 명, 로컬만. 읽음 버튼은 쓰기라 `/pick`과 같은 토큰 · 검사를 거친다. **읽음은 취소할 수 없다**(Finn 결정). 그래서 버튼을 누르기 전과 후의 모습이 분명히 달라야 한다.

## 4. 상태

| 상태 | 보이는 것 |
|---|---|
| 정상 | 카드 3장(제목 · 요약 · 링크 · 읽음 버튼 또는 읽음 표시) + 잔디 |
| 로딩 | 첫 응답 전 카드 영역에 한 줄 대기 문구(`wait-line`) |
| 오늘 0건 | 이유 한 줄 "오늘 동향 0건"(에러가 아님). 잔디와 지난 미읽음은 그대로 |
| 설정 없음 | 화면 위 한 줄 안내(`inline-note`) "동향 파일 경로 설정 없음" + 카드 자리에 빈 상태 카드 |
| 파일 없음 | 같은 방식, 문구 "동향 파일 없음" |
| 형식 확인 필요 | 같은 방식, 문구 "형식 확인 필요". 깨진 줄은 건너뛰었다는 개수를 안내 줄에 같이 |
| 읽음 파일 설정 없음 | 카드는 보이되 읽음 버튼이 막히고 그 자리에 이유 "읽음 파일 설정 없음" |
| 읽음 쓰기 실패 | **그 카드 안에** 에러 한 줄, 카드는 읽지 않음 그대로, 버튼은 다시 누를 수 있다 |
| 요청 실패(목록) | 요청 실패 한 줄 + 마지막 정상 화면 유지 |

- 조용히 비어 보이면 안 된다. 위 네 가지 이유(설정 없음 · 파일 없음 · 형식 확인 필요 · 오늘 0건)는 서로 다른 문구로 구분한다
- 카드 상태: **읽지 않음 / 요청 중 / 읽음**. 읽음은 되돌릴 수 없다는 것이 화면에서 분명해야 한다
- 요약이 길면 줄을 이어 보인다(회고 · 판정 카드와 같은 규칙, 줄 수 상한은 `DESIGN.md`)

## 5. 잔디 (이 화면의 핵심)

- **칸 하나 = 하루**, 진하기는 4단계: 0건 · 1건 · 2건 · 3건 이상(3 상한). 단계는 건수 그대로이고 비율이 아니다
- 기간은 **오늘을 끝으로 1년**. 가로로 주 단위 열, 세로로 요일(GitHub 방식)
- 칸이 채워지는 날은 **글이 나온 날**이다. 지난 날 글을 오늘 읽으면 오늘이 아니라 그 날 칸이 진해진다(Finn 결정)
- 칸에 hover하면 툴팁: `날짜 · n건 읽음`(색만으로 전하지 않는다)
- 4단계가 눈으로 구별돼야 한다(PRD 수용 조건 10). 색 사용 규칙: 한 가지 의미색의 진하기로 단계를 만들고, 0단계는 빈 칸처럼 보이되 격자는 남긴다
- 쓰기 시작한 처음 몇 주는 대부분 0단계 빈 칸이다(감수). 이때 화면이 고장 난 것처럼 보이지 않도록 달 이름 · 요일 라벨은 처음부터 있다
- 색 선택(기존 의미 역할을 쓸지, 잔디 전용 색 단계를 새로 둘지)은 `DESIGN.md`에서 정한다 — 아래 「미결」

## 6. 폼 · 쓰기

| 동작 | 위치 | 결과 | 비활성 조건 |
|---|---|---|---|
| 읽음 | 카드마다 버튼 하나 | 카드가 읽음으로 바뀌고 해당 날짜 칸이 한 단계 진해짐 | 요청 중 · 읽음 파일 설정 없음 · 이미 읽음 |
| 링크 열기 | 카드의 링크 | 새 탭으로 열림. 열기만 하면 읽음이 아니다 | `http(s)`가 아닌 주소는 링크가 아니라 글자로만 |

에러는 해당 카드 안에 인라인. 전역 토스트를 쓰지 않는다.

## 7. 인터랙션

- 메뉴: 좌측 메뉴에 그룹 하나 추가(아이콘 + 「기술 동향」, 하위 「오늘」 · 「안 읽은 글」). 3역량과 같은 그룹 펼침 · 하위 선택 규칙. 접으면 아이콘만. 그룹을 누르면 「오늘」이 열린다(열자마자 오늘 3건 요건)
- 「안 읽은 글」은 날짜순 목록, 글마다 날짜 · 제목 · 요약 · 링크 · 읽음 버튼. 읽으면 그 줄이 목록에서 빠지고 해당 날짜 잔디 칸이 진해진다. 0건이면 "안 읽은 글 없음" 빈 상태 카드
- 키보드: 읽음 버튼 · 링크에 Tab으로 닿고 포커스가 보인다
- 읽음을 누르면 그 자리에서 카드 상태가 바뀌고 잔디 칸이 바뀐다(전체 화면 새로고침 없이)
- 폴링은 기존 규칙(보이는 탭만 15초). 갱신 때 스크롤 위치와 요청 중 상태가 사라지면 안 된다

## 8. 재사용 후보 (코드 이름, 확정 아님)

`app-shell` · `shell-nav-item`(새 항목) · `inline-note`(설정 · 파일 안내) · `empty-state-card`(이유 있는 빈 상태) · `wait-line` · `button`(읽음) · `status-dot-label`(읽지 않음 / 읽음) · `tooltip`(잔디 칸). 새로 필요한 것: **잔디 칸 격자**(기존에 없음, 컴포넌트 신규 후보 — 쓰는 곳이 이 화면 하나라 로컬 컴포넌트로 시작), **동향 카드**(`decision-card`와 모양이 가까워 재사용 가능 여부를 시안에서 본다).

## 9. 제약

- 외부 패키지 없음, 응답 문자열은 마크업으로 해석하지 않음(요약 · 제목 · 링크 포함)
- 사람 이름 · vault 원문을 화면에 넣지 않는다(동향 글의 출처는 wiki가 준 제목 · 링크만)
- 다크 바탕 위 글자 대비 확인, 색만으로 뜻을 전하지 않는다(잔디는 툴팁과 건수 텍스트를 병행)

## 10. 비목표
